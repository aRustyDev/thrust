# Accessibility checklist for dioxus-components work

Evidence base: the registry README states the primitives follow the WAI-ARIA Authoring Practices and
"all styling can be modified via props"; the items under "What the primitives already do" were read in
`primitives/src/{dialog,alert_dialog,tabs,toast,popover}.rs` and `button/style.css` (`main`, 2026-10-18).
Items under "What you must still do" are general WCAG 2.2 / ARIA practice, not statements from the
Dioxus repositories. This checklist is a procedure, not a certification: it does not replace testing
with a screen reader.

## What the primitives already do (read in source)

- **Roles and relations:** Dialog `role="dialog"`, Alert Dialog `role="alertdialog"`, Tabs
  `tablist` / `tab` / `tabpanel`, Toast `region` / `alert`; attributes seen: `aria_modal`,
  `aria_labelledby`, `aria_describedby`, `aria_label`, `aria_hidden`, `aria_selected`, `aria_controls`,
  `aria_atomic`. Ids for these are generated (`dxc-<n>`) unless you pass `id`.
- **Modal dialogs (web and webview renderers; see the platform caveat below):** `is_modal` defaults to
  `true` and traps focus (docs on the prop); Escape closes (`use_global_escape_listener`); click outside
  dismisses (`use_outside_dismiss`).
- **Tabs keyboard:** Arrow keys move focus (orientation via `horizontal`), Home and End jump, optional
  looping (`roving_loop`).
- **State hooks for CSS:** `data-state`, `data-disabled`, `data-orientation`.
- **Button focus:** the styled Button resets `outline` but restores a `:focus-visible` indicator
  (`border-color: var(--focused-border-color)` plus a tinted ring).

## What you must still do

1. **Name everything.** Every icon-only `Button` gets an accessible name (`aria_label: "Close"`);
   every `Input`, `Textarea`, `Select`, `Checkbox`, `Switch`, `Slider` has a `Label` (matching
   `for`/`id`) or `aria_label`. A Dialog needs a `DialogTitle` and, where useful, a `DialogDescription`: they
   take their ids from the dialog's context and are wired to `aria_labelledby` / `aria_describedby`
   automatically, so do not wire the ids by hand (pass `id` only to override).
2. **Keep a visible focus indicator.** If you override `outline`, `border-color` or `box-shadow`, keep a
   `:focus-visible` style with at least 3:1 contrast against adjacent colours (WCAG 2.2 SC 1.4.11).
   Do not remove the base `--focused-border-color` ring.
3. **Check contrast after theming.** After overriding any `--primary-color-*` / `--secondary-color-*`
   / status variable, check text at 4.5:1 (3:1 for large text) in **both** schemes. Verify with a
   contrast tool; do not eyeball the two-branch `var(--dark, ..) var(--light, ..)` values.
4. **Do not rely on colour alone** for error, success or warning: pair the status colours with text or an
   icon, and set `aria_invalid` on the invalid control (the Button stylesheet has an
   `[aria-invalid="true"]:focus-visible` rule; the other components follow their own rules).
5. **Return focus.** On closing a Dialog / Popover / menu opened by a button, focus must return to the
   trigger. For Dialog this is built in: the focus trap remembers the previously focused element and
   refocuses it when the trap is removed on close (`dialog.rs`, `focus-trap.js`). `[unverified: Popover,
   menus and other overlays; test each one you ship]`
6. **Keyboard-only pass.** For each interactive component you add: Tab reaches it in a sensible order;
   Enter and Space activate buttons and triggers; Escape closes overlays; arrow keys work in
   Tabs, Menus, Radio Group, Select, Slider; no keyboard trap other than an intentional modal one.
7. **Reduced motion.** If you add animation around overlays, honour
   `@media (prefers-reduced-motion: reduce)`.
8. **Live regions.** Toasts announce via a live region; keep the message short and do not put the only
   copy of an error in a toast that auto-dismisses.
9. **Custom components** (the ones with no registry entry, see `mapping.md`): use native elements first
   (`button`, `a`, `input`, `dialog`-like patterns only if you replicate the APG keyboard model).

## Platform caveat

Under the native (dioxus-native) renderer the Dialog, Alert Dialog and Popover primitives lose the
behaviours that depend on `document::eval` (focus trap and focus restoration, escape-to-close,
outside-dismiss, exit animation). The verified detail has one owner: see the `blitz-native` skill. Test
overlays on every renderer you ship.

## How to report the outcome

For each component: the checks above that you ran (keyboard pass, contrast pass, labels), the ones you
could not run (screen reader, native renderer), and any `[unverified]` items left open.
