# Research 0007 — Plane quirks catalogue

**Status:** documentation deliverable, round 27. Written from the pinned oracle worktree and its recorded artefacts, plus the pre-pin docs worktree for the Part F deltas. No Plane code was executed and no system under test was started; analysis scripts and `diff` ran over files, and no git command was run against any Plane worktree. Evidence, counts and the commands that produced them are in "Method and coverage" at the end.

## Purpose and owner decision

Contrail/Thrust is a Rust rewrite of Plane that must stay wire-compatible with the **pinned** Plane (`oracle/v1-pin-20261018` -> `ba85d4d3d3`, upstream preview `879ce8b5c6`, package 1.4.2). The owner decided in round 27: **reproduce all of Plane's 500 responses (no `fix` deviations) and document all Plane quirks for planning and context.** This file is that documentation. It does not propose fixes and does not take decisions: where a quirk is a bug it is recorded as a bug that is to be reproduced. The Decision column therefore reads `reproduce` for every v1 and compat-plane behaviour, and `informational` only where there is nothing to reproduce (transport headers, dead code, fork-only plumbing). Two consequences for the other plan files, recorded here for the coordinator and not applied: `DEVIATIONS.md` candidates C-1..C-4 are all `reproduce` now (C-1 was recommended `fix`), and `oracle/exceptions.yaml` EX-001/EX-002 carry `rust_expectation: fix`, which round 27 supersedes.

**Clarification (coordinator, after review).** The owner's round-27 decision covers exactly two things: **reproduce all of Plane's 500 responses** and **document every quirk**. The `reproduce` in the Decision column of every other entry is the **default under ADR-0031 and ADR-0034** (stay wire-compatible with the pinned Plane), not a separate owner decision. Two entries are security-relevant and need an explicit decision before anyone reproduces them: **PQ-412** (any valid API key reads the attachment metadata of any project) and **PQ-413** (`POST .../cycle-issues/` re-points other projects' or tenants' issues). They conflict with SPEC R-S1 (tenant predicate) and ADR-0141. **Decided in round 27 (Q-0033.3): fix both as deviations D-014 and D-015**, so their Decision cell reads `fix`.

## Corrections and contradictions found while verifying

1. **EX-011 reason.** The register says search results omit `id`. They do not (corpus `work_items.json#search`); the schema documents a flat `IssueSearch` but the body is the `{"issues":[...]}` wrapper (PQ-309).
2. **EX-010 cause.** The sticky create/list mismatch is a drf-spectacular **component-name collision** on `Sticky`, visible in the run log; the link/activity detail mismatch is a decorator documenting a dead `pk is None` branch (PQ-307, 308).
3. **EX-004 and EX-003 partly measure the fixture.** The seeded projects have `cycle_view`, `module_view` and `intake_view` off, so every cycle/module create or PATCH and every intake POST/PATCH returns the same 400 `non_field_errors`; the success shapes of those families were never exercised (PQ-056, 314).
4. **EX-001 is incomplete.** It names `per_page` and the asset bug. Also reproducible: a `deleted_at` body on work-item/issue create (PQ-404), a non-object `issue` on intake create (PQ-405), array bodies (PQ-406), and two more `is_server` sites that the harness could not reach (PQ-401).
5. **Corpus asset exchanges.** `workspace-asset-get-not-uploaded`, `-mark-uploaded` and `-get-uploaded` use the placeholder id `MISSING-cap.wa`, so their 404 is the URLconf `Page not found.`; the "surprise" on `workspace-asset-mark-uploaded` is a harness artefact, not evidence about the handler.
6. **R3 section 9 row 4 and section 5 (19 slashless calls).** Superseded by the pinned client, which appends `/` to every API URL (PQ-109, 514).
7. **R3 section 7.5/9 on the 401 interceptor and `?t=`.** At the pin the interceptor skips `/` and URL-encodes the path, and `?t=` survives only on `users/me/settings/` (PQ-210, 514).
8. **R5 "only a missing key is 401".** Holds, and adds deactivated-user keys (PQ-501); pre-pin v1 error handling was itself (by inference) broken by `return exc` (PQ-503), so pre-pin observations of v1 error bodies should not be reused.
9. **R3 section 15.3 "29 changed v1 rows, not listed".** The v1 deltas are now listed (PQ-501..513).
10. **Quantities.** The pinned tree has 55 `self.paginate(` sites (26 v1) and 3 `default_per_page` overrides (R3 pre-pin: 49 sites and 2 overrides); 28 `sanitize_order_by`/`order_issue_queryset` call sites (R3: 18); 8 and 11 `useSWR` hooks in the workspace and project wrappers (R3 counts 9 and 13 *reads*).
