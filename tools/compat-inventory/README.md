# compat-inventory

The static inventory of the Plane internal API that spike 0009 (desk half) ran against the Plane fork: Django URL
confs read with `ast`, React/TypeScript call sites, the join between them, the `FEATURES.md` tags and the effort
model. Its pinned output, `out-pinned/endpoint-inventory.csv`, is the current F-X13 acceptance list. Method and
numbers: [`research/0003-compat-plane-inventory.md`](../../.agents/plans/contrail/research/0003-compat-plane-inventory.md).

This is tooling, not product code. No crate imports it (ADR-0006 register, round 29).

## Running it

Python is run through `uv` only. Every script carries a PEP 723 header (`requires-python = ">=3.11"`,
`dependencies = []`) and uses the standard library only, so there is no `pyproject.toml` and no lock file to keep.

```sh
uv run tools/compat-inventory/run_all.py --root <plane tree root> --out <output dir>
```

`--features` defaults to `.agents/plans/contrail/FEATURES.md`. `--out` defaults to `tools/compat-inventory/out/`,
which is ignored by git. The pre-pin output (`300c2009d4`) is not committed: it is regenerated by running
`run_all.py` against that tree.

## Reproducing `out-pinned/`

`ROOT` must be a real git checkout of the pin tag `oracle/v1-pin-20261018` (`ba85d4d3d3`) of the Plane fork, not a
`git archive` export: the default `--vcs files` reads the commit from the tree's `.git` pointer. The tag is in the
fork's clone, not on GitHub.

```sh
ROOT=<checkout of oracle/v1-pin-20261018>
OUT=$(mktemp -d)
uv run tools/compat-inventory/run_all.py --root "$ROOT" --out "$OUT" \
  --label 'oracle/v1-pin-20261018 -> ba85d4d3d3 (upstream preview 879ce8b5c6)' \
  --verdicts tools/compat-inventory/handcheck-verdicts-pinned.csv

diff -ru tools/compat-inventory/out-pinned "$OUT" \
  -x RUN.json -x layout-report.json -x pin-verify.json -x delta-vs-prepin.json \
  -x server-warnings.txt -x tables.md
```

The diff prints nothing and exits 0. Two of the flags are needed for a reason that is not obvious:

- `--verdicts` selects the hand-check verdicts for the pinned tree. The default `handcheck-verdicts.csv` is for the
  pre-pin tree and is stale on 29 of the 30 sampled rows, so `precision-recall.json` would differ.
- `pin-verify.json` (written by `verify_api_tree.py`) and `delta-vs-prepin.json` (written by `compare_runs.py`) are
  not produced by `run_all.py`. `RUN.json` and `layout-report.json` hold the scan root and the tree's metadata.

The last two exclusions are compared separately, because each differs in exactly one known way:

```sh
# server-warnings.txt: the committed copy has <root> where the scan root was.
sed "s|$ROOT|<root>|" "$OUT/server-warnings.txt" | diff tools/compat-inventory/out-pinned/server-warnings.txt -

# tables.md: line 1 stamps the commit that was scanned. The committed copy was scanned at 72b2e01497, the pin plus
# three harness commits that touched only apps/admin/.../oidc/; a checkout of the tag stamps ba85d4d3d3.
diff <(tail -n +2 tools/compat-inventory/out-pinned/tables.md) <(tail -n +2 "$OUT/tables.md")
```

Both print nothing. Run the same command against the pre-pin tree (`300c2009d4`) as a control: 18 of the output
files then differ in content, including `endpoint-inventory.csv` and `.json`.

`endpoint-inventory.csv` is the F-X13 acceptance list. A regenerated copy matches the committed one byte for byte.
